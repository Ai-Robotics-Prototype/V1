### Section 528: The hold defect — every layer executed in isolation, the bug found in the residue

Method: rather than another on-robot session, the operator supplied both repos (V1 + CodroidROS2) and the shipped code was **executed off-target**:

1. **Pinned regression `test_jog_hold_heartbeat`: 5/5 PASS** against the pushed source — the production deploy-watcher's DEPLOY FAILED banner is its own stale environment, not a code defect.
2. **In-vitro dashboard hold** (real `dashboard_server.py`, `JOG_BACKEND=ros2`, stubbed rclpy, true frontend cadence — 100 ms WS hold frames + 60 ms keepalive ticks for 3 s): **27 fanout events — 1 start, 25 refreshes at 101–137 ms gaps (zero over the bridge's 300 ms deadman), 1 stop, correct fields, zero legacy leakage.** The dashboard half of the hold path is exonerated by execution.
3. **Bridge SM simulation** (real `state_machine.py` + `limits.py`, driven by that exact captured stream, with a simulated JTC arm): **27 goals, sustained motion +81° over the 3 s hold, clean IDLE.** The SM is exonerated in isolation.
4. **The residue:** with every code layer clean, the recorded rung-3 fingerprint (presses dying *in the browser*, `ws_msgs_in` never bumping, zero network) pointed at the frontend's umbrella gate — **`jogGateOk = bannerLevel==='ready'`** — and what flips the banner: the CRI proxy's **staleness watchdog** sets `enabled=False` after `js_age > 1.0 s`, and its co-condition `estun_stale` is *structurally always true* in ros2 sessions (WS driver down → its status timestamp never updates), collapsing an AND into a single 1-second tripwire. What stalls `/joint_states` ingestion >1 s in a 250 Hz process? **The PIL camera-encode thread pinning the GIL** — caught red-handed by py-spy on the Jetson at 107% CPU.
5. **Unified theory of the night:** rung 2's 12/12 landed in a clean window; a GIL stall then crossed 1.0 s → chip flipped DISABLED → gate slammed → every subsequent press died silently in the browser → and every "I CANNOT ENABLE THIS ROBOT" was the operator reading a banner a camera thread had tripped, while the arm held enabled at 250 Hz throughout.

**Fix shipped, committed, pushed (V1):** staleness threshold 1.0 → 3.0 s with **hysteresis** (3 consecutive stale checks to flip down, one fresh JS to restore); **flip counters** on `/health` (`cri_proxy_flips`, last flip age — the instrument that converts this theory into proof or refutation on the next run); **`CAMERAS_DISABLED=1`** env to remove the GIL hog entirely for jog/test sessions; unit tests on the loop with a fake clock. Honest uncertainty recorded at ~85% — and the bundle check then **strengthened the case while widening the fix**: the *served* frontend bundle was **built August 6**, predating the seam, the banner chain audited, and everything since. **Next hardware session step 1 is `npm run build`** — both candidate causes (watchdog flap, stale bundle gate logic) are addressed regardless of which was the killer.

### Section 529: Cartesian jog unblocked from a tripwire of its own — the safety-edge retune (directed)

Operator, jogging cartesian on the WS backend, blocked repeatedly by "safety edge" stops far from any physical limit — and demanded all limit errors removed short of actual contact. **Refused as stated, retuned as deserved:** the pre-emptive margin exists because 52% of cartesian jog cutouts once hit the hard wall with no warning (controller alarm → wedge — the July disease); firing only *at* the limit guarantees overshoot into the controller's own stop. But the dynamic margin (`vmax × speed_frac × latency × 1.5`) was grossly over-conservative — at modest speeds it inflates the no-go zone by tens of degrees. **Directive issued:** latency term replaced with the system's own *measured* stop latency (F1.4: 56–61 ms → 0.15 s with buffer), safety factor 1.5 → 1.2, **dynamic margin capped at 5.0°**, static base 2.0° retained, cartesian soft-zone ramp scaled to match, **every stop/slowdown prints its numbers in the toast** (§285), pinned regressions (permitted at limit−6°, refused at limit−1°, escape always permitted). *Status: directed; completion to be confirmed in Claude Code's report.*

### Section 530: Recovery modal lifecycle — the dialog learns whose job it is (directed)

Operator: the joint-recovery modal auto-dismisses the instant the joint escapes the zone — mid-press — stranding the joint at the cliff edge when the goal is mid-range. Code confirmed: existence keyed on `past_escape_only`, 1.8 s success flash, unmount fires the hold's release under the operator's finger. **Directive issued:** never dismiss while a recovery hold is active (suppress the cleared-transition until release); after release-outside-zone, a persistent success state with the SAME live jog button (toward zero, crawl speed) plus an explicit **Done** — no auto-close; the 1.8 s auto-close survives only for the never-touched-the-button case; multi-joint re-assert unchanged; regressions pinned; **frontend rebuild required** for it to be real. *Status: directed.*

## PROCESS LESSONS (244–250)

244. **Exonerate layers by executing them off-target before debugging on-target.** The hold bug was cornered without a robot: the pinned regression, an in-vitro run of the real dashboard code at true cadence, and a simulation of the real SM against the captured stream each cleared a layer — leaving the bug in the residue (a frontend gate fed by a watchdog). Harness-execution of shipped code is cheaper than hardware sessions and produces evidence, not theories.

245. **A liveness watchdog's threshold must exceed the watched process's worst legitimate stall — and beware co-conditions that are structurally always true.** A 1.0 s tripwire on a process whose camera thread demonstrably pins the GIL past 1 s guarantees false trips; and `estun_stale` being always-true in ros2 sessions silently collapsed a two-condition guard into that single tripwire. Thresholds come from measured stall distributions; every AND-guard gets audited for degenerate always-true legs; every flip gets a counter.

246. **The served bundle's build date is part of every frontend diagnosis.** The browser was running an Aug 6 build — predating the seam and the audited gate logic — so source-reading was reasoning about code the user never executed. "Verified didn't mean shipped" (L227), frontend edition: check the bundle hash/date before trusting any frontend source audit, and rebuild before retesting.

247. **Safety margins scale from measured latency, not assumed latency — and dynamic terms get caps.** The speed-scaled limit margin used a guessed latency × 1.5 and inflated the no-go zone by tens of degrees, blocking legitimate jog; the system's own measured stop latency (56–61 ms) supports a margin 10× smaller. Pre-emptive protection stays (the 52% hard-wall history); its arithmetic must be earned by measurement, capped, and printed in every refusal.

248. **Dialog lifecycle keys on operator intent, not condition-clearing.** The recovery modal dismissed itself — mid-press — the instant the metric crossed its threshold, stranding the operator short of their actual goal. Modals that host a control stay while the control is in use, and close on the operator's explicit Done; the system's threshold is not the operator's finish line.

249. **The ledger is a transaction log; sessions load a materialized view.** At 1.1 MB the append-only monolith was defeating its own purpose — context exhaustion caused the very state-loss it existed to prevent. Split: small always-loaded distillates (doctrine, current state, constants, index) + grep-on-demand per-addendum archive; STATE.md rewritten each session end and authoritative for *current* truth, the ledger authoritative for *history*; append-only preserved where it matters. Numbering audits belong to the index build (L90's recovery and the 1–5 restatement were caught, not smoothed).

250. **Anything whose death costs work runs in tmux — including the AI session itself.** Claude Code sessions dying to Wi-Fi drops re-taught Lesson 217 one layer up: the tool orchestrating checkpoint-safe work must itself be checkpoint-safe. `tmux new -s claude`, detach, reattach; `--continue` for the context; on-disk artifacts for the state.
